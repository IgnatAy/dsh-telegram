# 可复制进 DSH AGENTS.md 的输出约束

以下约束适用于通过当前 dsh-telegram 插件发送的回复：

- 使用普通 Markdown，不要预先按 Telegram MarkdownV2 转义整段回复，也不要直接输出 HTML 标签来排版。
- 可以使用标题、粗体、斜体、粗斜体、删除线、行内代码和围栏代码块。标题统一显示为粗体，不依赖字号区分层级；避免复杂的多层样式嵌套。
- 引用的 `>` 必须放在行首。可以使用单层引用及 `[!NOTE]`、`[!TIP]`、`[!IMPORTANT]`、`[!WARNING]`、`[!CAUTION]` 提示块；嵌套引用会合并成一层，不依赖嵌套层级表达含义。
- 列表优先使用简单的 `-` 或 `1.`，避免深层缩进；代码优先使用三反引号围栏，保留真实换行。
- 链接使用 `[名称](https://地址)` 或完整网址，不使用 `[名称][ref]` 及文末引用式链接定义。
- Markdown 图片会转换为图片链接，不会直接作为照片上传。需要展示图片时，提供图片地址或使用明确支持的附件发送功能。
- 优先用列表或“字段：值”表达数据。表格只用于少量短字段，不依赖居中、右对齐、精确列宽或手机上不换行；表格当前是等宽文本模拟。
- 数学式使用可读的普通文本或 Unicode，如 `E = mc²`、`H₂O`；复杂公式放入代码块并附文字解释，不使用 `$...$`、`$$...$$` 来期待公式渲染。
- 不使用 `[^1]` 脚注语法、`~2~` 下标或 `^2^` 上标语法。注释写成正文中的“注：”，或使用普通编号和文末说明。
- 不使用 `<details>`、`<summary>` 等 HTML 折叠块。改用小标题和段落；不要依赖 HTML 标签、CSS 或交互式控件。
- 分隔线可以使用独立一行的 `---`，插件会显示为短横线。避免靠空格对齐正文，避免超长连续字符。
- 展示 Markdown、HTML 或 LaTeX 源码时，放入行内代码或围栏代码块，避免被当作排版语法处理。

## 维护说明（不必复制）

这些是当前插件的保守 Markdown 子集及普通文本消息通道的约束，不代表 Telegram 所有 API 的能力上限。原始 HTML、引用式链接、脚注、公式和折叠块目前保留为文本，不会猜测转换或丢弃内容。没有自动修改项目或全局 AGENTS.md。
