# dsh 过程折叠到 Telegram 的映射

对照版本：DeepSeek Harness `0.1.5-rc.2`。实现位于 `src/transcript.ts`，由 `TelegramProgress` 维护每轮记录。

过程记录与最终正文合成一条 Rich Markdown 消息：外层 `<details>` 在前，最终正文在后。`/resend` 重发同一份完整内容。

外层标题为 `x 次工具调用 · y 条消息`。工具数按 `tool/call` 启动次数统计，包括 subagent、失败和未完成调用；结果事件不重复计数。消息数按含可见文本的 `assistant/message` 统计，同一消息的多个文本块只计一次，最终答案所在步骤不进入中间记录。替换事件不追加记录。

展开后只有各条中间消息，依次显示粗体“消息 1”“消息 2”等编号，消息之间使用分隔线。文本块先合并，再保留原生 Markdown 的表格、公式、列表、链接和代码块。插件不添加内层折叠，不记录思考、工具名称、参数、结果或差异；完整过程仍在 DSH 历史中。

中间消息中未闭合的代码围栏和 details 在消息边界补齐，孤立的关闭 details 标签转义，避免吞掉分隔线、后续消息和最终正文。用户正文自带的有效富文本结构保持原样。

只有工具调用而没有中间消息时，折叠标题仍保留计数，内部显示“暂无中间消息。”。没有调用或中间消息时不生成过程折叠；纯思考且无可见答案的已完成任务只发送完成提示。

过程和最终正文共同受 Telegram 富消息长度限制；目前不自动截断或拆分。Rich Markdown 在 Telegram 服务端解析，本地测试验证内容、计数、边界和格式保留，不能代替真实客户端显示验证。
